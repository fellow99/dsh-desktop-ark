# 规格：上游适配层（105-upstream-adapter-bundle）

> 工程：`dsh-desktop-ark`
> 状态：`implemented`（profile 与 bundle 的 YAML 装配层 + 上游契约断言脚本）+ `planned`（seam 插件包）
> 来源：`docs/000-工程规划.md` §5.1–§5.5、§3.1、§14（D2/D5/D7/D13）；`specs/overall-spec.md` §5；`specs/overall-data-model.md` §7
> 需求语言遵循 RFC 2119（MUST / SHOULD / MAY）。本文件不含实现细节（不出现文件名、路径、API 名）。

---
## 1. 模块概述

**目的**：把上游 dsh 的平台相关行，经上游官方扩展点（profile / bundle / seam 插件）换成本工程可用的形态，且上游源码补丁数为 0。

**问题**：
- 上游默认假设桌面平台：本地子进程、内核沙箱、硬链接、原生图像库、配置文件热重载、整盘目录浏览；这些在 HarmonyOS 应用沙箱内多数不可用或有害。
- 逐版本打补丁会让升级成本随 rc 数量线性增长；fork 前端等于永久分叉。
- 平台降级若被隐藏，用户会把"不可用"当成缺陷。

**范围**：
- 范围内：组合顺序与覆盖语义；行级"禁用 / 覆盖 / 插入"三类操作的规则；seam 替换点清单；用户级 patch 的职责边界；上游契约的可执行断言；依赖安装参数约束；降级登记。
- 范围外：各 seam 插件内部实现（命令执行、沙箱策略、通知、诊断端点、目录选择界面分别由 106/107 与后续模块承担）、载荷打包与解包（102）、宿主能力面（104）。

**状态分解**（不得混写）：

| 组成 | 状态 |
|---|---|
| profile 清单（三包有序组合） | implemented |
| bundle 的 YAML 覆盖层（禁用/覆盖/插入） | implemented |
| 用户级 patch（空配置，设备可改、升级不覆盖） | implemented |
| 依赖安装参数（hoisted + copy + 跳过脚本） | implemented |
| 上游契约断言（tag、零补丁、行 id 存在性、清单可解析） | implemented |
| seam 插件包（子进程、沙箱策略、shell、目录选择、外部打开、通知、诊断、图像、sqlite） | **planned** |

## 2. 用户故事

- 作为维护者，我升级上游 tag 时只改版本号并重跑门禁，不需要逐个补丁重新对齐。
- 作为维护者，当上游把某个行 id 改名时，门禁立刻失败并指出是哪个 id，而不是运行时静默少加载一个能力。
- 作为用户，我看到的平台降级（无 PTY、无内核沙箱、无热重载）都有明确说明，不会表现为"功能坏了"。
- 作为开发者，我能在设备上调整自己的 profile 偏好，而升级应用时这些偏好不被覆盖。
- 作为维护者，我能用一条命令证明上游工作区零改动。

## 3. 功能需求

### 3.1 组合与覆盖

- **FR-105-001**：profile MUST 以固定顺序组合"上游基础层 → 上游 Web 界面层 → 本工程适配层"；顺序 MUST 稳定，因为后层按行覆盖前层。
- **FR-105-002**：bundle 覆盖层 MUST 只包含三类操作：按行 id 禁用、按行 id 覆盖整份配置、插入本工程提供的行；MUST NOT 复制上游行内容，MUST NOT 依赖"合并"语义。
- **FR-105-003**：覆盖某行配置时 MUST 重述该行全部自有键；MUST NOT 假定未列出的键会从上游继承。
- **FR-105-004**：插入行的 id MUST 全局唯一，且 MUST NOT 与上游已有 id 重名。
- **FR-105-005**：遇到无法识别的行 id MUST 报错并中止，MUST NOT 静默跳过（否则等于悄悄丢能力）。
- **FR-105-006**：用户级 patch MUST 只承载用户/设备偏好；平台适配 MUST NOT 写在该层（否则升级后行为漂移）。

### 3.2 平台行的处置

- **FR-105-007**：配置热重载行 MUST 在设备上禁用（无意义且增加文件系统压力）。
- **FR-105-008**：子进程行与沙箱行 MUST 由本工程实现替换；上游行 MUST 先禁用再插入，MUST NOT 让两套提供方同时在场。
- **FR-105-009**：沙箱策略行 MUST 保留，且其可写根 MUST 显式覆盖为绝对路径；MUST NOT 落回进程工作目录（真机上为 `/`）。
- **FR-105-010**：命令执行 MUST 由本工程的非 PTY shell 提供方承担；平台无 PTY 的事实 MUST 在文档与界面登记。
- **FR-105-011**：目录选择的自动装配行 MUST 禁用（它会动态挂载客户端面，无法被静态替换）；列目录/建目录的后端原语行 MUST 静态插入；对话框由本工程插件独占（规格见 `106`）。
- **FR-105-012**：外部打开行 MUST 由本工程经宿主能力面实现；仅放行工作区内文件与 https 链接。
- **FR-105-013**：通知行与诊断端点行 MUST 以插入行存在；诊断端点 MUST 默认关闭，正式构建 MUST 不可开启。
- **FR-105-014**：会话查询行 MUST 保留上游语义；其底层存储能力是否可用由垫片策略决定（见 `102`），本模块 MUST NOT 改写其配置语义。
- **FR-105-015**：所有降级与禁用项 MUST 在本模块文档中逐条登记"平台事实 / 决定 / 用户可见影响"，MUST NOT 只写"已适配"。

### 3.3 上游契约与依赖

- **FR-105-016**：上游 MUST 锁定到单一 tag；断言失败 MUST 以非零退出码结束。
- **FR-105-017**：上游工作区 MUST 零本地改动；断言 MUST 覆盖工作区状态。
- **FR-105-018**：断言 MUST 逐项检查本工程覆盖或插入所依赖的上游行 id 仍存在，并检查 profile 清单与 bundle 的 patch 声明可解析。
- **FR-105-019**：运行时插件安装的依赖布局 MUST 为"扁平 + 复制"，MUST NOT 依赖符号链接或硬链接；原生构建脚本 MUST 跳过。
- **FR-105-020**：本模块 MUST NOT 引入任何二进制产物；全部内容为文本配置与脚本。

## 5. 验收场景

### AC-105-01 profile 可组合
- **Given** 上游三个层各自可解析  
- **When** 按固定顺序组合并解析 profile  
- **Then** 组合结果中的每个行 id 唯一，且适配层的覆盖生效（对应用例 TC-105-001、TC-105-003）

### AC-105-02 行 id 改名即失败
- **Given** 上游某个被覆盖的行 id 改名  
- **When** 执行契约断言  
- **Then** 断言失败、退出码非零，并指出缺失的 id；MUST NOT 输出"通过"（TC-105-002）

### AC-105-03 可写根不是根目录
- **Given** 设备上进程工作目录为 `/`  
- **When** 解析沙箱策略行的配置  
- **Then** 可写根为显式绝对路径，且不等于 `/`（TC-105-004）

### AC-105-04 零补丁
- **Given** 上游检出处于锁定 tag  
- **When** 检查上游工作区状态  
- **Then** 输出为空（TC-105-005）

### AC-105-05 用户 patch 不被覆盖
- **Given** 用户修改了自己的 profile patch  
- **When** 应用升级后重新启动  
- **Then** 用户 patch 内容保留，适配层内容随版本更新

### AC-105-06 依赖安装不产生链接
- **Given** 沙箱拒绝符号链接与硬链接  
- **When** 安装运行时插件依赖  
- **Then** 安装完成且产物中没有链接，原生构建脚本未执行

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 可审计 | 每条覆盖/禁用/插入都能在单一文件中逐行读出，无需读代码 |
| 升级成本 | 升级 = 改 tag 与运行时版本 + 重跑断言；MUST NOT 需要修改上游源码 |
| 失败可见 | 契约断言失败 MUST 给出文件与 id，不允许"静默少一行" |
| 幂等 | 断言与安装参数写入可重复执行，结果一致 |
| 体积 | 本模块不产出二进制，体积贡献为 0 |
| 可回滚 | 覆盖层可整层移除，回退到上游默认行为 |

## 7. 假设与约束

- 上游 patch 的行结构（id / disabled / config / insert）在锁定 tag 内稳定；变化即视为契约变更（门禁失败是预期行为）。
- 配置值允许使用表达式在内核加载时求值；本工程只依赖"环境变量 → 配置值"这一条通道。
- 适配层的每个 seam 提供方包由本工程单独发布并随载荷物化；包未物化时该行 MUST 显式失败而非降级成功（planned 部分的验收前置）。
- 设备上无内核级沙箱、无 PTY、无符号/硬链接：这些是平台事实，不是待修缺陷。
- 上游版本与运行时版本成对锁定（见 `TECH.md` §5）。
