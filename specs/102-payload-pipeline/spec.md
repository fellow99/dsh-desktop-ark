# 102 载荷管线 —— 模块规格（spec）

> 模块：`102-payload-pipeline`｜状态：**部分 implemented（S1/S2 行为 + S3/S4/S5 仅探测，3 项 planned）**｜最后更新：2026-10-18
> 对应 spec：本文件；实现方案见 `specs/102-payload-pipeline/plan.md`

## 1. 模块概述

**目的**：把上游 dsh 运行树变成「随应用包分发、由进程内 Node 自己解包、带版本幂等键与平台垫片」的载荷，并在启动时把它安全地带到可运行状态。

**要解决的问题**

| # | 问题 | 本模块的回答 |
|---|---|---|
| P1 | 应用包内不能 spawn `tar`，运行时也没有解包工具 | 零依赖的 ustar + gzip 解包器，只接受白名单条目 |
| P2 | 外壳解出的文件 Node 读不到（沙箱视图不一致） | 解包**只由 Node 完成**，外壳只传归档绝对路径 |
| P3 | 重复启动不应重复解包 | 版本声明中的 sha256 派生幂等标记；标记与目标同时存在才跳过 |
| P4 | 鸿蒙缺失硬链接/符号链接/原生图像库/原生锁 | 5 条白名单垫片，每条有唯一标记与可审计结论 |

**范围内**：载荷装配、确定性归档、版本声明、解包、幂等标记、垫片安装与探测、自检、构建脚本的输入校验与退出码。
**范围外**：上游构建（pnpm build）、依赖裁剪规则、Host 启动、插件安装、profile/bundle 内容。

**现状（事实）**

| 能力 | 状态 |
|---|---|
| 归档生成（确定性 ustar + gzip）、版本声明 | implemented |
| Node 自解包、暂存→切换、幂等标记、sha256 校验 | implemented |
| 路径穿越/绝对路径/链接条目拒绝、截断检测 | implemented |
| 异常兜底（只落日志） | implemented |
| S1 硬链接回退、S2 符号链接回退 | implemented |
| S3 文件锁替身、S4 图像库替身 | **planned**（当前只探测替身包是否存在，不提供行为） |
| S5 内嵌 SQLite 重定向 | **not-implemented**（当前只测量可用性与 FTS5） |
| 旧版本载荷清理（保留最近 1 份） | **planned** |
| 装配阶段的上游物化、裁剪、覆盖层注入 | implemented（`pnpm deploy --legacy` + 链接物化 + `@deepseek-ai` 补全 + 非 hoisted 摊平 + 剪裁 + profile/插件注入 + 断言；装配后 15 192 文件 / 151 MiB） |

## 2. 用户故事

- 作为用户，我第一次启动时能接受一次性解包等待，之后每次启动都不再重复解包。
- 作为用户，载荷缺失或损坏时我能看到明确原因，而不是无休止转圈。
- 作为维护者，我能用同一条命令重跑载荷构建，并得到相同的归档哈希。
- 作为维护者，我能从自检输出判断每条垫片「装没装、是否真的生效」，而不是靠猜。

## 3. 功能需求（RFC 2119）

### 3.1 发布与幂等

- **FR-102-001**：随包载荷 MUST 以单一归档 + 一份版本声明发布；运行时 MUST NOT 依赖目录遍历推断版本。
- **FR-102-002**：版本声明 MUST 以 64 位十六进制 sha256 作为幂等键；缺失或非法时 MUST 报告「载荷缺失」，MUST NOT 猜测版本。
- **FR-102-003**：幂等标记 MUST 由 sha256 前 12 位派生；标记与目标树同时存在时 MUST 跳过解包，缺一 MUST 重新解包。
- **FR-102-004**：解包 MUST 先落暂存目录，成功后再切换到目标目录；中断 MUST NOT 让半成品被后续启动复用。
- **FR-102-005**：归档完整性 MUST 在解包前校验；sha256 不一致 MUST 失败并给出可诊断结论。

### 3.2 解包安全与诚实

- **FR-102-006**：解包 MUST 只由运行时自身完成；外壳 MUST NOT 写入运行时将要读取的树。
- **FR-102-007**：解包 MUST 拒绝绝对路径、含上溯段的路径、逃逸解包根的路径，以及符号链接/硬链接等非普通条目。
- **FR-102-008**：解包 MUST 只接受 ustar 普通文件与目录；非 ustar、条目截断 MUST 立即失败。
- **FR-102-009**：解包过程 MUST 以阶段公告暴露进度；失败 MUST 写入终态诊断，MUST NOT 只打日志。
- **FR-102-010**：载荷缺失 MUST 以独立阶段上报，并说明期望的归档路径、版本声明路径与运行根。

### 3.3 垫片

- **FR-102-011**：平台垫片 MUST 限于 5 条白名单（硬链接、符号链接、文件锁、图像库、内嵌 SQLite）；MUST NOT 出现第 6 条未登记垫片。
- **FR-102-012**：每条垫片 MUST 有唯一标记字符串与一行安装日志；MUST 在启动最早期安装，早于任何上游模块加载。
- **FR-102-013**：垫片 MUST 可审计：自检 MUST 报告每条垫片的安装状态与探测事实，MUST NOT 把「替身包不存在」报告成已安装。
- **FR-102-014**：垫片 MUST 只做「平台能力缺失的等价替代」，MUST NOT 掩盖业务逻辑差异。
- **FR-102-015**：未捕获异常与未处理拒绝 MUST 被兜底：只落日志、MUST NOT 主动退出进程（启动阶段致命错误除外）。

### 3.4 构建与脚本

- **FR-102-016**：载荷构建脚本 MUST 幂等可重跑；相同输入 MUST 产生逐字节相同的归档与相同的版本声明首行。
- **FR-102-017**：脚本在缺少必需输入时 MUST 以非零退出码失败并说明下一步；MUST NOT 静默成功。
- **FR-102-018**：二进制产物（运行时库、归档、HAR）MUST NOT 入库；MUST 由脚本投放或生成。
- **FR-102-019**：升级后 MUST 保留上一版本载荷以便回滚，启动时只清理非当前版本（保留最近 1 份）。
- **FR-102-020**：自检 MUST 以机器可读输出与退出码表达结论；全部通过为 0，任一失败为非 0。

## 4. 关键实体

### 4.1 载荷归档（PayloadArchive）

单个 gzip 压缩的 ustar 归档；顶层目录固定为 `dsh/`；条目只有普通文件与目录；无 pax 扩展、无链接、无设备文件。

### 4.2 版本声明（PayloadVersion）

一行四个字段：`sha256`（64 hex）、`fileCount`、`bytes`、`builtAt`（ISO 时间）。sha256 是幂等键；缺失时只能报告载荷缺失。

### 4.3 幂等标记（ExtractionMarker）

位于载荷根下、以 `sha12` 命名的标记文件；内容记录 sha256、文件数、完成时间；与目标树成对判定。

### 4.4 垫片登记（ShimRecord）

每条记录包含：唯一标记、是否已安装、探测到的额外事实（替身包路径、SQLite 可用性与 FTS5 结果）。

### 4.5 自检报告与就绪公告
- `SelfcheckReport`：`{ ok, results[] }`，每条 `{ name, ok, detail }`，覆盖垫片、目录可写性、公告结构。
- `ReadyInfo`：`preparing`/`extracting`/`payload-missing`/`starting`/`ready`/`failed`，供模块 101 消费；写入 MUST 原子。

## 5. 验收场景

### TC-102-001 版本声明驱动幂等标记
- **Given** 版本声明含合法 sha256　**When** 首次解包完成
- **Then** 生成以 sha12 命名的标记，内容含完整 sha256 与文件数；**证据**：标记文件

### TC-102-002 重复启动跳过解包
- **Given** 标记与目标树都存在　**When** 再次启动
- **Then** 不执行解包，只复用运行根；两次启动耗时可对比；**证据**：日志 + 计时

### TC-102-003 归档损坏时失败且不破坏旧版本
- **Given** 归档哈希与版本声明不一致　**When** 启动
- **Then** 解包不发生，目标树不被删除，公告进入载荷缺失/失败态；**证据**：脚本退出码 + 日志

### TC-102-004 五条垫片各有一行标记
- **Given** 载荷可运行　**When** 启动完成
- **Then** 安装日志中每条垫片的唯一标记各出现一次，自检逐条报告；**证据**：业务日志 + 自检 JSON

### TC-102-005 硬链接被拒时回退改名
- **Given** 平台对硬链接返回权限错误　**When** 上游发布会话产物
- **Then** 回退为同目录改名且目标已存在时仍然失败；**证据**：自检输出 + 日志

### TC-102-006 未捕获异常不终止进程
- **Given** 启动完成后注入一个未捕获异常　**When** 观察进程
- **Then** 只新增一行异常日志，应用仍存活；**证据**：业务日志 + 进程存活

### TC-102-007 归档路径穿越被拒绝
- **Given** 归档含 `../` 条目　**When** 解包
- **Then** 立即失败且不写出任何逃逸文件；**证据**：解包报错

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 首启性能 | 单次解包 ≤ 25 秒（预算）；已解包启动不产生解包 I/O |
| 内存 | 解包 MUST 不因归档体积导致应用被系统回收（当前实现为整包读入，峰值约 2 倍归档解压后体积） |
| 可复现 | 同输入归档 hash 与版本声明首行稳定；构建脚本可重跑 |
| 安全 | 解包 MUST NOT 写出解包根之外的任何路径；MUST NOT 接受链接条目 |
| 可观测 | 解包文件数、耗时、失败原因 MUST 可在业务日志检索 |
| 体积 | 归档计入 HAP 预算（HAP ≤ 200 MB 未压缩） |

## 7. 假设与约束

- **归档格式单一**：只支持 ustar（无 pax、无长名扩展）；超长路径必须在打包阶段被拒绝，而不是静默截断。
- **单进程**：文件锁替身按「单进程」语义等价，不能跨进程互斥。
- **谁写谁读**：解包者必须是运行时自身；外壳只提供归档绝对路径。
- **无网络**：构建与解包均不下载任何依赖。
- **脚本运行环境**：构建脚本在宿主 Node ≥ 18 上执行；投放脚本面向 Windows + Git Bash（依赖 `cygpath`/`cmd`）。
- **状态标注**：S3/S4 只做探测、S5 只做测量、旧版本清理与装配物化未实现——已在 §1.4 与 `plan.md` 标 `planned`/`not-implemented`。
