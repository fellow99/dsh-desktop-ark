# 101 运行时启动编排 —— 模块规格（spec）

> 模块：`101-runtime-launch-orchestration`｜状态：**implemented（1 项 planned）**｜最后更新：2026-10-18
> 对应 spec：本文件；实现方案见 `specs/101-runtime-launch-orchestration/plan.md`

## 1. 模块概述

**目的**：把应用从冷启动带到「主界面可以加载本机服务地址」的状态，并把过程变成可观察、可诊断、不可自动重试的状态机。本模块只做编排与判定，不做界面渲染、载荷解包与服务实现。

**要解决的问题**

| # | 问题 | 本模块的回答 |
|---|---|---|
| P1 | 进程内 Node 启动是异步「投递」，返回时并未就绪 | 「准备→启动→等待→探活」四段推进，每段有明确判据 |
| P2 | 就绪信号由 Node 侧写文件，可能缺失或半截 | 以服务自报公告为唯一依据；缺失即失败，不猜端口 |
| P3 | 失败后无法重启 Node（每进程只能一次） | 失败即终态；诊断可复制，恢复靠重启应用 |
| P4 | 用户只看到白屏或转圈 | 每次阶段迁移同步产出一帧快照供界面渲染 |

**范围内**：运行期目录准备、运行时投递、就绪等待、公告回读与校验、回环探活、快照广播、失败诊断汇总、退出通知。
**范围外**：Node 内部启动与 Host 监听、载荷解包与垫片、页面渲染与导航、宿主能力实现、自动重启。

**现状（事实）**

| 能力 | 状态 |
|---|---|
| 阶段状态机 + 快照广播 | implemented |
| 运行期目录幂等创建 | implemented |
| 运行时投递与投递失败处理 | implemented |
| 公告回读、字段校验、探活、失败诊断 | implemented |
| 公告**在启动预算内重试读取** | **planned**（as-built 只读一次，见 plan §3） |
| `READY` 阶段独立对外可见 | **not-implemented**（枚举有值，流程未使用） |
| 退出时广播 `STOPPED` 快照 | **not-implemented**（只改内部状态） |

## 2. 用户故事

- 作为用户，我打开应用后不需要配置，就能看到「准备 / 启动 / 等待 / 确认」的明确阶段，而不是空白窗口。
- 作为用户，启动失败时我能看到阶段、原因、日志尾与崩溃记录，并一键复制发给维护者。
- 作为维护者，我能按阶段定位失败点，且不会看到「自动重试」掩盖真实问题。
- 作为维护者，我重启应用即可重试，因为进程内运行时没有第二次启动机会。

## 3. 功能需求（RFC 2119）

### 3.1 编排与幂等

- **FR-101-001**：同一应用进程内运行时启动 MUST 只发起一次；重复调用 MUST 只重放最近一帧快照，MUST NOT 二次投递。
- **FR-101-002**：启动前 MUST 幂等创建运行期目录（载荷根、临时、会话家目录、工作区、桥、信箱）；已存在 MUST 视为成功。
- **FR-101-003**：启动 MUST 按固定阶段推进「准备→启动→等待→探活→运行」，每次迁移 MUST 同步广播快照（阶段、说明、详情、入口地址）。
- **FR-101-004**：从投递到可用的总预算 MUST 为 60 秒；超时 MUST 进入失败态并给出日志尾。

### 3.2 就绪与探活

- **FR-101-005**：就绪 MUST 以服务自报的公告为准；外壳 MUST NOT 自行拼接端口，MUST NOT 生成或校验凭据。
- **FR-101-006**：公告 MUST 通过结构与取值校验（阶段为 `ready`、入口地址非空）；不合法或不可解析 MUST 失败，MUST NOT 以默认值继续。
- **FR-101-007**：公告 MUST 在启动预算内被重试读取直至出现或预算耗尽（**planned**，as-built 只读一次）。
- **FR-101-008**：探活 MUST 对回环地址做有界重试（20 次 × 500 毫秒）；任何 HTTP 响应（含 4xx/5xx）MUST 视为监听存在。
- **FR-101-009**：探活成功后 MUST 将运行时标记为运行中，并把公告中的入口地址交给界面。

### 3.3 失败、诊断与恢复

- **FR-101-010**：任一阶段失败 MUST 汇总失败原因、运行日志尾（≤200 行）与最近崩溃记录（阶段、信号、时间、提示）。
- **FR-101-011**：失败详情 MUST 可复制，MUST NOT 含凭据或完整的带凭据入口地址。
- **FR-101-012**：失败 MUST 为终态；MUST NOT 自动重试或自动重启运行时；恢复 MUST 由用户重启应用完成。
- **FR-101-013**：标记运行时失败时 MUST 尽力记录原因；标记动作自身失败 MUST 只记日志，MUST NOT 覆盖原始原因。

### 3.4 路径、退出与生命周期

- **FR-101-014**：运行期路径 MUST 由沙箱目录与资源目录派生且为绝对路径；MUST NOT 依赖进程工作目录或可执行路径。
- **FR-101-015**：收到系统终止回调时 MUST 通知运行时收尾并立即放行终止；MUST NOT 拦截、MUST NOT 等待优雅停止。
- **FR-101-016**：退出通知 MUST 只记录原因并广播「正在退出」；进程内运行时无优雅停止接口，MUST NOT 宣称已停止。
- **FR-101-017**：宿主能力面 MUST 在运行时投递之前完成注册与传输启动，保证启动期能力调用不丢失。

## 4. 关键实体

### 4.1 启动阶段（LaunchPhase）

`IDLE`、`PREPARING`、`STARTING`、`WAITING`、`PROBING`、`READY`、`RUNNING`、`FAILED`、`STOPPING`、`STOPPED`。`FAILED` 为终态；`READY` 在 as-built 中未被使用（直接进入 `RUNNING`）；合法主干只有一条，任一阶段可跳 `FAILED`。

### 4.2 启动快照（LaunchSnapshot）

| 字段 | 含义 | 约束 |
|---|---|---|
| `phase` | 当前阶段 | 必填，取值为上文枚举 |
| `message` | 面向用户的一句话 | 必填，不含凭据 |
| `detail` | 失败详情 | 仅失败时非空，可复制 |
| `url` | 入口地址 | 仅 `RUNNING` 非空，含一次性凭据，**不得写入日志** |

### 4.3 就绪公告读取视图（ReadyInfo）

字段：`schema`、`phase`、`url`、`origin`、`token`、`pid`、`version`、`diagnostic`。读取方 MUST 容忍未知字段（向前兼容）；as-built 只校验阶段与入口地址，`schema` 尚未校验（见 plan §3）。

### 4.4 崩溃记录与投递结果

- `CrashRecord`：`at`（epochMs）、`stage`、`signal`（可选）、`hint`（可选）、`logTail`。
- `NodeStartResult`：`ok`、`code`（`0` 已投递；`>0` 原生线程创建错误码；`<0` 参数/状态校验失败）、`state`、`message`。

## 5. 验收场景

### TC-101-001 载荷存在时 60 秒内进入运行态
- **Given** 随包载荷完整、运行时已投放　**When** 冷启动应用
- **Then** 阶段依次经过准备、启动、等待、探活并在 60 秒内进入 `RUNNING`，界面加载自报入口地址；**证据**：公告文件 + 截图

### TC-101-002 载荷缺失时给出可复制诊断
- **Given** 归档与运行树均不存在　**When** 启动应用
- **Then** 进入失败态，详情含「未找到可运行载荷」、期望路径与日志尾且可复制；**证据**：截图 + 业务日志

### TC-101-003 就绪公告字段合法
- **Given** 运行时已写公告　**When** 外壳读取公告
- **Then** 仅在阶段为 `ready` 时采用其入口地址与凭据，其它阶段判失败；**证据**：公告样本

### TC-101-004 探活失败时进入失败态
- **Given** 公告指向未监听端口　**When** 探活 20 次全部失败
- **Then** 进入失败态且详情含被探测地址；**证据**：截图 + 日志时间戳

### TC-101-005 启动超时不挂起
- **Given** 投递成功但永不就绪　**When** 等待超过 60 秒
- **Then** 进入失败态，界面不冻结且可复制详情；**证据**：日志时间戳 + 截图

### TC-101-006 重启应用可重试
- **Given** 已处于失败态　**When** 用户经重启入口退出并重新打开应用
- **Then** 新一轮启动可重新投递，同一进程内 MUST NOT 出现第二次投递；**证据**：截图序列 + hilog

### TC-101-007 崩溃后不自动重启
- **Given** Node 已崩溃　**When** 外壳读取崩溃记录
- **Then** 展示阶段、信号与提示，MUST NOT 自动重启；**证据**：崩溃记录文件 + 截图

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 启动性能 | 已解包载荷冷启动到首屏 ≤ 10 秒；首次启动（含解包）≤ 60 秒 |
| 状态可见性 | 每次迁移 MUST 在 100 毫秒内反映到界面（同步回调） |
| 稳定性 | 任一阶段异常 MUST NOT 使应用进程退出；失败只改变状态 |
| 可观测 | 任一失败 MUST 能在业务日志与 hilog 中找到阶段与原因 |
| 隐私 | 入口凭据 MUST NOT 进入日志；失败详情 MUST 脱敏 |
| 可访问性 | 阶段与失败原因 MUST 以文本呈现，不得只用图标或颜色 |

## 7. 假设与约束

- **单进程、单实例**：Node 运行在应用进程内；进程内运行时每进程只能启动一次，失败不可在进程内恢复。
- **公告由服务侧写入**：外壳只是消费方；公告的原子写与幂等由模块 102 负责。
- **随机端口**：外壳不指定端口，端口由服务侧以「端口 0」申请。
- **路径事实**：真机上进程工作目录为 `/`、可执行路径为系统宿主，MUST 不作为判断依据。
- **状态标注**：本文档描述目标行为；as-built 差异（公告无重试、`READY` 未使用、`STOPPED` 未广播）在 `plan.md` §3 列出，未实现项标 `planned`。
- **平台依赖**：探活依赖系统网络栈访问回环地址，受门禁 G1 约束。
