# 规格：诊断与可观测（107-diagnostics-observability）
> 工程：`dsh-desktop-ark`
> 状态：四通道日志、就绪报告、日志尾与崩溃记录、自检脚本 **implemented**；本机事实端点、日志轮转、凭据扫描断言 **planned**
> 来源：`docs/000-工程规划.md` §5.3（垫片纪律）、§6.7、§11.3；`specs/overall-spec.md` §3.6；`specs/overall-plan.md` §4.2；`specs/overall-test-cases.md` §9

## 1. 模块概述
**目的**：让"启动失败/能力异常/插件异常"在设备上可取证、可复制、可判断责任边界，并且不泄露凭据。

**问题**：
- 运行时崩溃是终态（进程内运行时不可重启），现场一旦丢失就只能靠复现。
- 原生输出、运行器输出与外壳输出共用同一文件描述符，日志容易被互相污染；不隔离就永远读不出阶段。
- 失败时用户只看到白屏或"启动失败"三个字，无法把原因交给维护者。
- 诊断常常顺手把入口 URL 里的凭据一起打出来，形成新的安全问题。

**范围**：
- 范围内：四通道日志（运行时日志 / 业务日志 / 系统日志 / 崩溃记录）、启动阶段埋点、就绪报告的原子写与失败诊断、日志尾与崩溃记录在失败页的呈现、自检脚本的断言与退出码、调试专用的本机事实端点、脱敏与导出纪律。
- 范围外：上游会话与工具日志（上游自带）、遥测/上报（明确不做）、性能剖析、崩溃自动上报。

**状态分解**：

| 组成 | 状态 |
|---|---|
| 运行时日志（标准输出/错误，含原生输出） | implemented |
| 业务日志（阶段、垫片标记、异常兜底） | implemented |
| 系统日志（统一域与标签） | implemented |
| 崩溃记录（阶段、信号、时间、提示） | implemented |
| 就绪报告（原子写 + 失败诊断） | implemented |
| 失败页的日志尾（截断行数）+ 一键复制 | implemented |
| 自检脚本（垫片探针、目录可写、就绪报告结构） | implemented |
| 本机事实端点（仅调试构建） | **planned** |
| 日志单文件轮转 | **planned** |
| 凭据/令牌扫描断言 | **planned** |
| 每条垫片的自检断言齐备 | **planned**（当前只覆盖三条） |

## 2. 用户故事
- 作为用户，启动失败时我能看到"卡在哪个阶段 + 原因 + 最近日志"，并能一键复制给维护者。
- 作为用户，我能确定复制出去的内容里没有我的登录凭据。
- 作为维护者，我拿到一份日志就能判断是载荷缺失、上游启动失败、端口不可达，还是原生崩溃。
- 作为维护者，我能用一条命令在设备上验证垫片与目录是否真的可用，而不是靠"看起来生效"。
- 作为开发者，我能在调试构建上用只读端点看到运行事实（版本、端口、插件行、垫片、能力标志），正式构建看不到。

## 3. 功能需求
### 3.1 四通道
- **FR-107-001**：应用 MUST 提供四类可取证信息：运行时日志、业务日志、系统日志、崩溃记录。
- **FR-107-002**：四通道 MUST 各自独立存放或独立可检索，MUST NOT 因共用输出流而互相覆盖。
- **FR-107-003**：业务日志 MUST 逐条记录启动阶段迁移（准备/解包/启动中/就绪/失败），每条 MUST 带时间戳。
- **FR-107-004**：系统日志 MUST 使用统一且全局唯一的域与标签，标签 MUST 能按应用过滤。
- **FR-107-005**：每条平台垫片 MUST 在业务日志留下唯一可 grep 的标记行；标记 MUST NOT 出现在非垫片代码中。
- **FR-107-006**：未捕获异常与未处理的 Promise 拒绝 MUST 写入业务日志，MUST NOT 导致进程退出（启动阶段致命错误除外）。
- **FR-107-007**：崩溃记录 MUST 至少包含发生阶段、信号或错误类别、时间、可执行提示。
- **FR-107-008**：日志 MUST NOT 记录入口凭据、Cookie、模型 API key；只 MAY 记录其存在性与长度类摘要。

### 3.2 就绪报告与失败呈现
- **FR-107-009**：就绪报告 MUST 原子写入（临时文件 + 重命名），读取方 MUST 永不看到半截 JSON。
- **FR-107-010**：就绪报告 MUST 携带 schema 版本、阶段、时间戳；仅在就绪阶段携带入口地址与凭据；失败阶段 MUST 携带诊断文本。
- **FR-107-011**：启动失败时界面 MUST 显示阶段、原因、日志尾（固定上限行数）与「重启应用」入口。
- **FR-107-012**：诊断文本 MUST 可一键复制到本地剪贴板；复制内容 MUST 与界面展示一致。
- **FR-107-013**：就绪报告缺失、损坏或 schema 不符时 MUST 归因为明确原因，MUST NOT 崩溃或静默重试。
- **FR-107-014**：崩溃记录只 MAY 读取展示，MUST NOT 触发自动重启。

### 3.3 自检
- **FR-107-015**：自检 MUST 输出机器可读的单份报告（结论 + 逐项结果），全部通过时退出码为 0，否则非零。
- **FR-107-016**：自检 MUST 覆盖：垫片安装/回退行为、运行期目录可写、就绪报告结构（若存在）。
- **FR-107-017**：自检 MUST NOT 把"能力不存在"记成失败样本（例如存储能力缺失是事实，应记录其可用性与能力标志）。
- **FR-107-018**：自检 MUST NOT 因就绪报告尚未生成而失败（冷启动可接受）。
- **FR-107-019**：每条垫片 MUST 有对应自检断言（当前仅三条，缺的两条为主要缺口）。

### 3.4 调试端点与治理
- **FR-107-020**：调试构建 MUST 提供只读的本机事实端点；正式构建 MUST NOT 暴露该端点，也 MUST NOT 允许运行期开启。
- **FR-107-021**：事实端点 MUST 使用与主界面相同的鉴权口径（同源 Cookie），MUST NOT 明示或隐含凭据。
- **FR-107-022**：事实端点 MUST 返回：运行时版本与 ABI、profile 名、监听端口、插件行状态、垫片清单、能力标志。
- **FR-107-023**：事实端点 MUST NOT 返回入口凭据、Cookie 或用户目录内容清单；用户目录只报存在性与授权态。
- **FR-107-024**：日志文件 MUST 单文件轮转并有上限；轮转 MUST NOT 丢失当前启动阶段之后的内容。
- **FR-107-025**：诊断导出 MUST 只在用户主动操作时发生；应用 MUST NOT 静默上报任何诊断数据。

## 5. 验收场景
### AC-107-01 四通道互不覆盖
- **Given** 应用经历一次正常启动
- **When** 同时取运行时日志、业务日志、系统日志与崩溃记录
- **Then** 四份样本各自存在且内容不互相截断（TC-107-002）

### AC-107-02 阶段可读
- **Given** 载荷缺失
- **When** 打开失败页并复制诊断
- **Then** 文本包含失败阶段、原因与最近日志，且有「重启应用」入口（TC-107-001、TC-102-002）

### AC-107-03 凭据不出现在诊断中
- **Given** 应用已就绪并生成入口地址
- **When** 复制失败页诊断或检索业务日志
- **Then** 检索不到凭据及 Cookie（TC-107-004）

### AC-107-04 自检可判定
- **Given** 设备上已安装应用
- **When** 运行自检
- **Then** 输出单份机器可读报告；全通过时退出码为 0；存储能力缺失只体现为能力标志而不判失败（TC-107-005）

### AC-107-05 调试端点
- **Given** 调试构建且已就绪
- **When** 访问本机事实端点
- **Then** 返回版本、端口、插件行、垫片与能力标志，且不含凭据；正式构建访问同一路径 MUST 不可用（TC-107-003）

### AC-107-06 崩溃后不自动重启
- **Given** 运行时已崩溃并留下崩溃记录
- **When** 回到界面
- **Then** 展示崩溃记录摘要与重启入口，MUST NOT 自动重启运行时（TC-101-007）

## 6. 非功能需求
| 类别 | 要求 |
|---|---|
| 可用性 | 日志不可写时 MUST 降级到错误流，MUST NOT 阻塞启动 |
| 时效 | 任一失败 MUST 在 5 s 内可读到原因（界面或日志） |
| 容量 | 日志单文件有上限；日志尾展示上限固定（约两百行） |
| 隐私 | 无静默上报；诊断只在用户主动复制时导出 |
| 可读性 | 阶段名与错误标识符保持英文；诊断文本中文可读 |
| 一致性 | 系统日志的域与标签 MUST 来自单一常量来源，不得散落硬编码 |
| 幂等 | 自检与就绪报告写入可重复执行，结果一致 |

## 7. 假设与约束
- 运行时库提供日志缓冲与崩溃记录的读取接口；本模块不自行解析原生崩溃栈。
- 原生输出与外壳输出共用输出流是平台事实，因此业务日志必须独立文件，不能依赖标准输出。
- 事实端点依赖上游的行插入机制（`105`）与调试构建开关（`108`）；两者未完成前端点无法存在。
- 日志中允许出现绝对路径（排障必需），但 MUST NOT 出现目录内容清单与凭据。
- 设备取证通道为系统调试桥（截图、注入点击、拉取沙箱文件、系统日志过滤），不接受"看起来生效"作为判据。
- 崩溃是终态：不设计自动重启、不做崩溃上报。
