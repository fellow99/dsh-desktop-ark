# 104 宿主能力桥 —— 模块规格（spec）

> 模块：`104-host-capability-bridge`｜状态：**部分 implemented（6 项能力可用，8 项 not-implemented）**｜最后更新：2026-10-18
> 对应 spec：本文件；实现方案见 `specs/104-host-capability-bridge/plan.md`

## 1. 模块概述

**目的**：给运行时侧的 Node 代码提供一条受控、可审计、永不抛异常的通路，去调用宿主（ArkTS）才有的能力：运行时事实、权限、外部打开、日志，以及后续的选择器、通知、剪贴板、图像处理。

**要解决的问题**

| # | 问题 | 本模块的回答 |
|---|---|---|
| P1 | Node 线程不能直接调用系统 API | 冻结命名的能力面 + 文件信箱传输，JSON 字符串进出 |
| P2 | 平台能力有缺失，调用方容易拿到「假成功」 | 未注册回 `unregistered`，未实现回 `not-implemented` + 提示 |
| P3 | 处理器异常会让调用方永久等待 | 所有异常映射为结构化错误；传输层永不 reject |
| P4 | 调用需要可诊断 | 每个中间态都是文件；有心跳与统计串 |

**范围内**：能力注册表、请求/响应信封、错误码、载荷上限、串行分发、信箱文件生命周期、已实现能力的语义。
**范围外**：Node 侧调用封装（属运行时库/上游插件）、具体业务插件、通知/选择器的产品逻辑、鉴权。

**现状（事实）**

| 能力 | 状态 |
|---|---|
| 能力注册（14 个冻结名）与错误信封 | implemented |
| 信箱扫描、取走（改名）、串行分发、结果回写、心跳、陈旧回收 | implemented |
| 运行时事实、日志、权限查询/申请、应用信息页、外部打开 | implemented |
| 目录选择（3 项）、通知、剪贴板读图/写文本、常亮（7 项） | **not-implemented**（占位） |
| 图像规范化 `image.normalize`（ImageKit 解码/缩放/编码） | **implemented**（2026-10-20；真机图片对话通过） |
| 运行时事实中的「能力状态」字段 | **not-implemented**（字段缺失） |
| 工作区内文件的外部打开 | **not-implemented**（只放行 https） |
| 仓库内 Node 侧能力调用方 | **not-implemented**（无任何调用点） |
| 单次调用 10 秒处理器超时 | **not-implemented** |

## 2. 用户故事

- 作为运行时侧的插件，我可以用一个名字 + 一段 JSON 调用宿主能力，并按错误码决定重试、降级或提示用户。
- 作为用户，当某个能力还没做时，我看到的是「未实现 + 为什么」，而不是无声失败或假成功。
- 作为维护者，我能从信箱目录与心跳判断桥是否在工作、卡在哪个请求。
- 作为维护者，我能确认能力面不传递任何凭据，也不承担鉴权职责。

## 3. 功能需求（RFC 2119）

### 3.1 命名与信封

- **FR-104-001**：能力名 MUST 采用 `<域>.<动作>` 形式并冻结；首批 MUST 为 14 个，新增 MUST 同步文档。
- **FR-104-002**：请求与响应 MUST 为 JSON 字符串；MUST NOT 依赖参数位置、可选参数或类型重载。
- **FR-104-003**：请求 MUST 具备唯一标识（由文件名承载）、能力名、已序列化参数、写入方进程号与时间戳。
- **FR-104-004**：成功响应 MUST 为 `{ok:true, result}`；失败 MUST 为 `{ok:false, error, hint}`；`hint` MUST 是可执行提示。
- **FR-104-005**：错误码 MUST 是封闭集合：`unregistered`、`not-implemented`、`bad-args`、`payload-too-large`、`internal`（传输层另有 `handler-threw`、`async-handler-on-sync-path`）；新增 MUST 同步文档。

### 3.2 分发与错误

- **FR-104-006**：处理器 MUST NOT 抛异常；任何异常 MUST 映射为 `internal` 并保留原始消息摘要。
- **FR-104-007**：未注册能力 MUST 返回 `unregistered`；已注册未实现 MUST 返回 `not-implemented` + 提示；MUST NOT 返回伪成功。
- **FR-104-008**：参数为空、无法解析或超过上限 MUST 在调用处理器之前被拒绝（`bad-args` / `payload-too-large`）。
- **FR-104-009**：单次载荷上限 MUST 为 8 MiB，按 UTF-8 字节计；超限 MUST NOT 截断。
- **FR-104-010**：分发 MUST 串行：同一时刻最多一个请求在处理；异步能力 MUST 在处理完成前阻止下一次取件。

### 3.3 信箱传输

- **FR-104-011**：请求 MUST 先写临时文件再原子改名；MUST NOT 让读方看到半截 JSON。
- **FR-104-012**：空文件或不以 `}` 结尾的请求 MUST 视为未写完，MUST NOT 消费、MUST NOT 阻塞队首。
- **FR-104-013**：处理中 MUST 以改名标记「已取走」；成功/失败 MUST 各写结果文件并清理中间态。
- **FR-104-014**：陈旧中间文件 MUST 在阈值后回收；正在处理的那一个 MUST 豁免。
- **FR-104-015**：传输 MUST 可观测：MUST 提供轮询轮次、分发次数、错误次数与心跳文件。

### 3.4 能力语义与安全

- **FR-104-016**：运行时事实 MUST 返回应用版本、期望运行时版本/ABI、绝对路径集合与用户目录列表；MUST NOT 含凭据。
- **FR-104-017**：用户目录可用性 MUST 以真实存在性/可访问性判定；不可用 MUST 如实上报，MUST NOT 恒为可用。
- **FR-104-018**：权限查询与申请 MUST 调用系统授权接口并回传真实授予结果；MUST NOT 伪造已授予。
- **FR-104-019**：外部打开 MUST 只放行 `https` 链接与工作区内文件；其它 MUST 拒绝并说明原因。
- **FR-104-020**：日志能力 MUST 保留级别与消息并写入系统日志；MUST NOT 记录凭据、cookie 或 token。
- **FR-104-021**：能力面 MUST NOT 成为鉴权面：MUST NOT 接收、解析或转发凭据；MUST NOT 改变服务监听地址。

## 4. 关键实体

### 4.1 能力请求（CapabilityRequest）

`id`（时间戳 + 序号，字典序即 FIFO）、`name`、`args`（JSON 文本）、`pid`、`ts`。

### 4.2 能力响应（CapabilityResponse）

成功 `{ok:true, result}`；失败 `{ok:false, error, hint}`。传输层另包一层：成功为 `{ok:true, result:"<转义后的响应串>"}`，失败为 `{ok:false, error, detail, dispatch}`。

### 4.3 运行时事实（RuntimeFacts）

`schema`、`app{bundleName, versionName, versionCode}`、`node{expected, abi}`、`paths{filesDir, resourceDir, payloadRoot, assetRoot, dshHome, workspace, mailbox}`、`userDirs[{id, path, available}]`、`jitless`。

### 4.4 信箱文件与能力清单
- 信箱五件套：`.tmp`（写）、`.req`（待处理）、`.wip`（处理中）、`.done`/`.fail`（结果）；另有不参与回收的 `heartbeat.log`。
- 冻结名（14 个）按域分：运行时事实、权限（查询/申请/应用信息页）、文件（目录选择/文件选择/文件保存）、外部打开、通知、剪贴板（读图/写文本）、图像规范化、日志、常亮。

## 5. 验收场景

### TC-104-001 运行时事实合法
- **Given** 桥已启动　**When** 调用运行时事实能力
- **Then** 返回合法 JSON，`paths` 全为绝对路径且不含凭据；**证据**：JSON 样本

### TC-104-002 未注册能力
- **Given** 名字不在注册表　**When** 调用
- **Then** 返回 `{ok:false,error:"unregistered"}`，不进入处理器；**证据**：调用输出

### TC-104-003 已注册未实现
- **Given** 调用通知能力　**When** 分发
- **Then** 返回 `not-implemented` 与可执行提示；**证据**：调用输出

### TC-104-004 权限查询真实
- **Given** 已声明与未声明权限各一　**When** 调用权限查询能力
- **Then** 分别返回 `granted` 的真假，不抛异常；**证据**：JSON

### TC-104-005 日志可检索
- **Given** 调用日志能力　**When** 在系统日志检索标签
- **Then** 能查到该消息；**证据**：hilog 片段

### TC-104-006 处理器异常不抛出
- **Given** 注入一个会抛错的处理器　**When** 调用
- **Then** 返回 `internal` + 提示，调用方不超时；**证据**：注入用例输出

### TC-104-007 超限载荷被拒
- **Given** 参数超过 8 MiB　**When** 调用
- **Then** 返回 `payload-too-large`，处理器未被调用；**证据**：调用输出

### TC-104-008 串行与陈旧回收
- **Given** 一个慢请求在飞　**When** 第二个请求排队
- **Then** 第二个不开始处理；在飞文件不被回收，超过阈值后其它中间态被回收；**证据**：目录快照 + 心跳

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 延迟 | 单次往返目标 ≤ 5 毫秒（真机信箱实测约 2 毫秒；含 100 毫秒轮询上限） |
| 吞吐 | 串行；宿主能力均为用户动作，不追求并发 |
| 稳定性 | 处理器与传输 MUST NOT 抛异常；坏请求 MUST 回填失败而不是等待超时 |
| 载荷 | 单次 ≤ 8 MiB（UTF-8 字节）；失败结果 ≤ 64 KiB（原生通道上限） |
| 可观测 | 心跳 ≥ 每 5 秒一次；统计串含轮次/分发/错误/回收 |
| 隐私 | 不记录凭据；事实端点只报路径与版本 |

## 7. 假设与约束

- **单进程、单实例**：信箱两侧同 UID、同文件系统视图；文件锁类能力不跨进程。
- **鉴权不在此处**：能力面不验证身份，也不承担页面进入的鉴权；调用方已在应用进程内。
- **同步面有限**：原生槽位通道是同步的，异步处理器只能走文件信箱；同步通道遇到 Promise 必须报错而不是返回未决结果。
- **能力名冻结**：改名等同破坏性变更；新增能力必须同时更新本文档与整体数据模型。
- **状态标注**：8 项占位能力、用户目录真实性、能力状态表、工作区文件外开、Node 侧调用方、处理器超时均为 `not-implemented`，见 `plan.md` §3。
