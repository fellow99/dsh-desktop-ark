# 鸿蒙环境能力清单 · 0.2.1（HarmonyOS Edition / dsh-desktop-ark）

> **适用版本**：`dsh-desktop-ark` 0.2.1（`versionName` 0.2.1 / `versionCode` 201，dsh `dsh-v0.2.1-rc.2`，运行时 libnode v24.2.0）
> **更新日期**：2026-10-21
> **基准**：能力集合与判定口径**以 `dsh-desktop-hos`（Electron on HarmonyOS）为基准**（见其 [`鸿蒙环境能力清单-0.2.1.md`](../../dsh-desktop-hos/docs/鸿蒙环境能力清单-0.2.1.md)）。本文件是同一张表在 **ArkWeb 路线**上的对标结论 + 本工程证据与待办。
> **本文只记结论**：逐项实测过程与复现步骤保留在 `docs/010-真机调试记录.md`、`docs/ACL*.md` 与 `logs/`（不入库）。
> **图例**：✅ 可用（有真机或等价实证）｜⚠️ 受限 / 部分可用 / 占位｜❌ 无此能力或已决策不做｜❓ 未取证。

## A. 环境标识（本工程 vs 基准）

| 项 | HarmonyOS Edition（本工程） | Electron on HarmonyOS（基准：`dsh-desktop-hos`） |
|---|---|---|
| 界面渲染 | 系统 ArkWeb（不随包带浏览器内核） | Electron 37 内置 Chromium |
| Node 运行时 | 进程内 `libnode.so` v24.2.0（`node::Start`） | Electron 内置 Node 22.17 |
| 平台适配方式 | 上游**零补丁**：`ohos` profile + `@dsh-ohos/bundle` + 6 条带标记垫片 + seam 插件 | 13 个上游源码补丁 + profile + 插件 |
| 运行时形态 | 默认 `compat`（`--jitless`，零 ACL）；`jit` 变体需 1 项 ACL | JIT（需受限权限 `ALLOW_WRITABLE_CODE_MEMORY`） |
| 沙箱策略 | `workspace-write`（`sandbox: none`，围栏在 `fs-sandbox` 与执行器层） | `workspace-write` + 审批 `ask` |
| 包体 | HAP ≈ 88 MB（含 42 MB 载荷归档） | HAP ≈ 数百 MB（含 Electron 运行时与 dsh-dist） |
| 已撤销的权限 | `READ_WRITE_DESKTOP_DIRECTORY`、`READ_PASTEBOARD`、`FILE_ACCESS_PERSIST` | 仍声明桌面目录权限（上架须移除） |

## C. 与基准相比的取舍

| 维度 | 本工程（ArkWeb 路线） | 基准（Electron 路线） |
|---|---|---|
| **赢** | 零 ACL 可安装、包体小（≈88 MB）、零上游补丁（升 tag 只重跑管线）、桌面权限已撤销、三根目录授权闭环、工作区选择器体验完整、品牌与首次引导可产品化 | 完整 Node/Chromium 语义、命令执行与纯 JS 搜索、文件变更原语齐全、托盘与窗口状态、插件市场、任意 ArkTS 能力桥 |
| **输** | 无命令执行（当前）、无搜索、无文件变更原语、无托盘/窗口状态/市场、能力桥固定 14 项 | 需 JIT 受限权限（上架依赖 ACL 获批）、补丁随 tag 维护、包体大 |
| **共同天花板** | 无 PTY、无进程沙箱、无开机自启、无静默更新、无服务端缩略图、2in1 无真正后台 | 同左 |

### D.2 待办（按优先级；含根因与修复点）

| 优先级 | 项 | 根因 | 修复点 |
|---|---|---|---|
| **P1** | `bash` 工具不可用 | `subprocess-ohos` 的 `assertExecutable()` 先 `statSync().isFile()`、`canonicalPath()` 用 `realpathSync()`；应用域对 `/system/bin/sh` 的 `stat/lstat/realpath` 返回 EACCES（`accessSync` 与 `execFile` 却正常） | 捕获 EACCES 时降级为"仅 `accessSync(X_OK)` 通过即放行"，并让 `canonicalPath()` 在 EACCES 时回退原路径；或对系统 shell/toybox 走白名单短路 |
| **P1** | `grep` / `glob` 不可用 | 载荷内 `@vscode/ripgrep` 无 `bin/rg`（也没有 aarch64-ohos 产物） | 与基准工程对齐：写纯 JS 的 grep/glob seam 插件（基于 `ctx.fs.listDir/readText`），或给 `tool-fs-search` 装纯 JS 后端 |
| **P1** | 删除 / 移动 / 复制 / chmod 缺失 | 上游 `ctx.fs` 无对应原语（L4） | 参照基准工程的三个补丁（remove / writeBytes / chmod）改为**物化期补丁**或自建 seam 工具包；短期也可在 `@dsh-ohos/git` 的 `fs-adapter` 上复用实现 |
| **P2** | 列目录工具缺失 | 无 `ls`/`view` 工具 | 随 grep/glob 插件一并交付 `ls`（或挂 `str_replace_editor` 的 `view`） |
| **P2** | 插件市场未集成 | `dsh-market` 未进 profile/bundles | 参照基准工程 012：随包纯 JS `pnpm` + `dshmarket` bundle 行；需评估载荷体积 |
| **P2** | 通知 / 剪贴板占位 | ArkTS 侧未实现对应能力 | 补 `notify.show`（`@kit.NotificationKit`）与 `clipboard.*`（`@kit.BasicServicesKit`），或明确标注"本版不交付" |
| **P3** | 能力桥仅 14 个冻结名 | 设计为白名单式文件信箱 | 需要新能力时扩展名单（含 Node↔ArkTS 双向通道与超时语义） |
| **P3** | 提权审批不可用 | `permission` 预设禁用（执行器无可隔离模式） | 与 P1 一起解决：命令执行可用后再评估审批预设 |
| **P3** | 窗口状态记忆 / 无边框 / 更新检查 | 未实现 | 按产品需要再决定，非阻塞 |
